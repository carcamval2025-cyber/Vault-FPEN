01

Pensar antes de programar

Antes de que R entre en escena: qué es un algoritmo, en qué orden se resuelve un problema de datos, y por qué "el código corrió sin errores" nunca es suficiente evidencia. Estas cinco preguntas son puramente conceptuales -- no necesitas RStudio abierto para responderlas.

Preg. 01

R contra RStudio

IA permitida

Una persona dice: “R es lo mismo que RStudio”. Explica qué hace cada uno y qué componente es el que realmente interpreta tus instrucciones.

0 / 40

Respuesta y criterios

  • R es el lenguaje y el motor que interpreta y ejecuta tus instrucciones: es el que realmente "entiende" el código.
  • RStudio es el entorno (IDE) que facilita editar scripts, usar la consola, ver objetos y gráficos: no interpreta nada por sí mismo.
  • Instalar solo RStudio sin R no sirve de nada: RStudio necesita a R para ejecutar cualquier instrucción.
Preg. 02

Qué es un algoritmo

IA permitida

Define algoritmo usando una tarea cotidiana (no de programación) con entradas, pasos y resultado. ¿Cómo comprobarías si tus instrucciones son suficientemente precisas?

0 / 50

Respuesta y criterios

  • Un algoritmo es una secuencia finita de instrucciones precisas que produce un resultado a partir de unas entradas.
  • Ejemplo: recibir un precio y un efectivo, comprobar que el efectivo alcanza, y devolver efectivo - precio como vuelto.
  • Se comprueba dándoselo a otra persona (o a R) sin explicar nada más: si puede seguirlo sin adivinar un paso, es suficientemente preciso.
Preg. 03

El orden importa

IA permitida

Ordena y explica estos cinco pasos: plantear pregunta, identificar datos, escribir instrucciones, verificar resultado, comunicar decisión. ¿Qué riesgo hay si empiezas directamente por el código?

0 / 50

Respuesta y criterios

  • Orden correcto: pregunta → datos → instrucciones → verificación → comunicación. Esta es la regla central de todo el curso.
  • Empezar por el código puede producir un cálculo perfectamente correcto para una pregunta que nadie necesitaba responder.
  • Sin una pregunta clara primero, no hay forma de saber qué datos hacen falta ni cómo verificar si el resultado "tiene sentido".
Preg. 04

Describir contra predecir

IA permitida

Contrasta una descripción de datos ya observados con una predicción de ventas futuras. ¿Qué pregunta responde cada una y cuál exige supuestos adicionales?

0 / 45

Respuesta y criterios

  • La descripción responde "¿qué ocurrió en los datos que ya tengo?": es un resumen de hechos observados.
  • La predicción responde "¿qué podría ocurrir fuera de esos datos?": requiere supuestos, un método y una forma de comprobar el desempeño de ese método.
  • Confundir ambas es común: un promedio histórico describe el pasado, no predice el futuro por sí solo.
Preg. 05

El salto a la causalidad

IA permitida

Un script que corre sin errores concluye: “más publicidad causa más ventas”, solo porque un gráfico muestra una tendencia ascendente. Señala el salto lógico y propone una formulación más defendible.

0 / 50

Respuesta y criterios

  • Que el código ejecute sin errores no demuestra que el análisis sea correcto: es una regla que va a repetirse todo el curso.
  • Una relación ascendente en un gráfico es asociación, no evidencia de causalidad: pueden existir otros factores no observados.
  • Formulación más defendible: “En estos registros, más publicidad se asocia con más ventas”, sin afirmar causa.

Preg. 06

Consola contra Script

IA permitida

La Consola y un Script ejecutan ambos 20 + 5. ¿Cuál de los dos te permite repetir mejor el análisis una semana después? ¿Por qué?

0 / 35

Respuesta y criterios

  • El Script conserva las instrucciones escritas y permite repetir el análisis completo más tarde, con quien sea.
  • La Consola es útil para pruebas rápidas e inmediatas, pero no organiza por sí sola un procedimiento reproducible: lo que escribes ahí se pierde.

Preg. 10

Instalar, cargar y usar

IA permitida

Distingue instalar, cargar y usar un paquete. ¿Qué instrucción pondrías en un Script reutilizable, y cuál NO conviene ejecutar cada vez que corres el script?

0 / 45

Respuesta y criterios

Tres formas de indexar

Sin IA

Si x <- c(8, 14, 11, 7), anticipa el resultado de x[c(1, 3)], x[-2] y x[x > 10]. Explica el criterio de selección de cada una.

0 / 50

Respuesta y criterios

  • Son tres mecanismos distintos: índices específicos, exclusión de índice, y filtro lógico.

Preg. 20

Tasa global contra promedio de tasas

IA permitida

Explica por qué una proporción global sum(asistentes) / sum(inscritos) puede diferir de mean(asistentes / inscritos). ¿Cuál usarías para "la proporción de todas las personas que asistieron"?

0 / 55

Preg. 22

Matriz contra data frame

IA permitida

¿Por qué una matriz construida con números y nombres puede convertir los números en texto, mientras un data frame puede preservar ambos tipos por separado?

0 / 50

Respuesta y criterios

  • Una matriz es un vector atómico con forma rectangular: solo admite un tipo de dato para toda la matriz. Si mezclas números y texto, todo se convierte a texto.
  • Un data frame (o tibble) es una colección de columnas, y cada columna conserva su propio tipo: una puede ser numérica y otra de texto, al mismo tiempo.
  • Por eso el curso usa data frames/tibbles para datos económicos reales (columnas mixtas), y reserva las matrices para datos puramente numéricos.

Preg. 31

color dentro y fuera de aes()

Sin IA

En geom_point(aes(color = punto)), ¿qué significa color dentro de aes()? Contrasta con geom_point(color = "red").

0 / 45

Respuesta y criterios

  • aes(color = punto) asigna el color según los valores de la variable punto: cada categoría recibe un color distinto y aparece una leyenda automáticamente.
  • geom_point(color = "red"), fuera de aes(), fija un color constante para todos los puntos: no depende de ningún dato, no genera leyenda.
  • Regla general: dentro de aes() = "varía según los datos"; fuera de aes() = "valor fijo para todo el gráfico".
Preg. 32

Mapeo global contra local

IA permitida

¿Cómo obtienes puntos coloreados por categoría y, al mismo tiempo, una única recta de tendencia negra (no una por categoría)? Explica la diferencia entre un mapeo global y uno local.

ggplot(datos, aes(x = visitantes, y = ingreso_usd)) + geom_point(aes(color = punto)) + geom_smooth(method = "lm", se = FALSE, color = "black")
0 / 50

Respuesta y criterios

  • Un mapeo puesto en ggplot(aes(...)) es global: se hereda por todas las capas (todas las geoms lo "ven").
  • Un mapeo puesto directamente en una geom, como geom_point(aes(color = punto)), es local: solo afecta a esa capa.
  • Solución: definir x e y globalmente, poner aes(color = punto) solo en geom_point(), y usar geom_smooth(method = "lm", se = FALSE, color = "black") sin mapeo de color: esa capa no se agrupa por categoría y dibuja una sola recta general.
Preg. 33

Qué controla binwidth

Sin IA

Un histograma y un polígono de frecuencias usan binwidth = 25. ¿Qué significa exactamente ese número? ¿Por qué cambiarlo puede alterar la lectura, aunque los datos no cambien?

0 / 50

Respuesta y criterios

  • binwidth fija el ancho de cada intervalo del eje x, en las mismas unidades que la variable (aquí, dólares).
  • Cambiar binwidth reagrupa las mismas observaciones en intervalos distintos: altera la forma visual (más o menos "ruido"), pero no cambia ni un solo dato original.
